# 自适应 FEC

主控连接的高级选项及设备编辑提供「自适应 FEC」，默认关闭，下次连接生效。数据报模式（混合、QUIC、VNT）协商成功后保护视频和音频；纯 TCP 不请求、不创建 FEC 状态。设备配置明确保存 `fecEnabled`，编解码器回退保留连接选择。

`Hello.fec_version` / `Welcome.fec_version` 使用版本 1，零表示关闭。首版两端均支持 FEC；请求与确认不一致时拒绝连接。内部 TCP IPC 只传递原始媒体和反馈，由最终 UDP 出口编码。

## 编码与边界

- 使用 `reed-solomon-erasure` 的 GF(256) 系统式编码，缓存有限的编码矩阵。原始包立即交给接收路径，无须等待校验包；恢复包走同一条解析、重组和去重路径。
- 外层沿用 15 字节分片头，flags 为 `0x08`，随后是版本、媒体类型、屏幕 ID、generation、64 位分组基序号、分片索引、数据片数、校验片数和千分比冗余目标。外层头共 38 字节，数据片编码原始包的两字节长度及完整原始数据报，校验片按最长数据片补零编码。
- 视频不跨帧编码，每组最多 32 个数据片、10 个校验片。音频默认每组两个 10ms 包（协议上限三个），在约 10ms 后发出校验片，为 20ms 纠错期限预留抖动余量；最多一个校验片，不跨 generation。所有数据报不超过现有的 1415 字节上限。
- 视频 FEC 分组使用 20ms 无进展期限及一秒硬上限；视频帧在 FEC 后进入独立的限时重传与依赖判断。音频从首次收包起最多等待 20ms，过期恢复包不再交付，无法恢复时使用 PLC，不参与视频重传。
- 接收端最多保留 1024 个在途分组、32 MiB 分片数据；关闭屏幕、切换 generation 和会话重建清理对应状态。整个分组丢失可通过后续分组的基序号识别；完全断流仍由现有帧间隔反馈和看门狗处理。

## 协议 v1：限时重传与参考链

- 每帧携带编码器代次、64 位帧标识、参考帧集合、独立恢复点及 `Unknown` 标记；每个 UDP 分片重复依赖描述。分片头 `0x10` 表示依赖扩展，屏幕路由后使用两字节大端长度加 protobuf，再接视频数据。所有扩展均从 MTU 预算扣除。Broker 为重启的采集代理映射新的连接内代次。
- H264 从参数集、I/P 切片参考列表及 MMCO 得到依赖；HEVC 跟踪单层短期／长期 RPS；AV1 跟踪参考槽、刷新、短参考信令推导及 `show_existing_frame`。不支持的语法（例如 H264 B／场图像、扩展／多层码流）或解析失败标记为 `Unknown`，丢帧后不得当作无依赖继续解码。不根据帧类型、GOP 层级或上一帧推测安全性。
- 发现缺口后先留 5ms 给乱序和 FEC；恢复预算固定为 `clamp(2 × RTT + 8ms, 20ms, 50ms)`，无近期 RTT 使用 30ms。静默尾片在 20ms 无进展后判定缺失。新包和重复包不延长已确定的截止时间；2ms 定时推进，最多两轮重传，剩余时间不足一个 RTT 时不再发送请求。
- 客户端通过认证控制通道发送 `VideoNack`，指定屏幕、generation、编码代次、帧标识及缺片范围；空范围表示整帧。每连接缓存最多 32MiB、150ms 的原始分片，只重发当前绑定地址的数据；队列有界、重复请求受限，重传与正常视频共享连接峰值预算。`0x20` 重传标记使原始分片直接进入重组，不受过期 FEC 组影响，FEC 原始丢包统计保持不变。
- 重组最多保留 16 帧、32MiB。重传失败但后续帧没有引用丢失数据时跳过丢帧继续播放；后续帧依赖丢失数据或无法确认依赖安全时，停止向解码器交付受影响帧，逐屏每 500ms 至多请求一次 IDR。已有完整独立恢复点时直接使用；单纯静默不请求 IDR，保留绑定重试和会话超时。
- 诊断按屏幕累计重传请求、首次请求时观察到的缺片／整帧缺失、成功重传帧、超时、最终丢帧、解码抑制帧及 IDR 原因。成功恢复不计最终丢帧，观察到的缺片及 FEC 原始丢包信号仍保留。

## 调节和统计

每秒分别反馈视频流及音频的原始数据片接收数、预期数、恢复数、残余丢失和收到的校验字节。等乱序窗口结束后再结算，迟到原始包不会与恢复包重复计数。连接详情汇总最近三秒内各流统计，恢复总数按连接累计。

初始冗余目标 5%，原始丢包率 EWMA 权重为 0.25。弱网目标为 `clamp(1.5 × p / (1 − p) + 2%, 0%, 30%)`；恶化时立即增加，连续健康五秒后每秒降低两个百分点，最低为零。超过三秒没有有效反馈会中断健康连续时间，不会自行恢复冗余或码率。RTT 明显上升、断流或发送压力期间禁止增加冗余。

校验包按累计字节预算取整，小组允许不发送校验包，实际校验数据报累计字节不超过累计原始数据报字节的目标比例。该比例不包含每个原始包新增的封装头。视频编码目标预留冗余空间，所有校验包及封装头计入现有 UDP 峰值限速和真实连接流量。纠错后的丢帧及 RTT 驱动降码率、降帧率机制。
